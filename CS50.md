# CS50 2025 (Based on Latest Available) - Week 7: SQL

## Overview

Week 7 introduces databases and Structured Query Language (SQL). Students learn how to design relational databases, create tables, and use SQL commands to insert, query, update, and delete data. Key concepts include primary keys, foreign keys, relationships between tables, and basic database design principles. The week often uses SQLite as the database engine due to its simplicity and file-based nature.

## Lectures, Explanations, and Shorts

### Lecture 7:
*   **What is a Database?**
    *   An organized collection of data, generally stored and accessed electronically.
    *   Why use databases over, say, CSV files? Scalability, data integrity, concurrent access, relationships, efficient querying.
*   **Relational Databases:**
    *   Data organized into tables (relations).
    *   Tables have rows (records/tuples) and columns (fields/attributes).
    *   Relationships between tables (one-to-one, one-to-many, many-to-many).
*   **SQL (Structured Query Language):**
    *   The standard language for interacting with relational databases.
    *   DDL (Data Definition Language): `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`.
    *   DML (Data Manipulation Language): `INSERT`, `SELECT`, `UPDATE`, `DELETE`.
*   **SQLite:** A lightweight, file-based SQL database engine often used in CS50.
    *   Using `sqlite3` command-line interface.
    *   `.schema`, `.tables`, `.import` commands.
*   **Basic SQL Commands:**
    *   `CREATE TABLE table_name (column1_name DATATYPE, column2_name DATATYPE, ...);`
        *   Data types: `INTEGER`, `TEXT`, `REAL`, `NUMERIC`, `BLOB`, `NULL`.
        *   Constraints: `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, `DEFAULT`.
    *   `INSERT INTO table_name (column1, column2) VALUES (value1, value2);`
    *   `SELECT column1, column2 FROM table_name WHERE condition ORDER BY column LIMIT n;`
        *   `*` to select all columns.
        *   `WHERE` clause: `AND`, `OR`, `=`, `!=` or `<>`, `<`, `>`, `<=`, `>=`, `LIKE` (for pattern matching with `%` wildcard), `IN`.
        *   `ORDER BY column ASC|DESC`.
        *   `LIMIT` and `OFFSET`.
        *   Aggregate functions: `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`.
        *   `GROUP BY` clause.
        *   `DISTINCT`.
    *   `UPDATE table_name SET column1 = value1 WHERE condition;`
    *   `DELETE FROM table_name WHERE condition;`
*   **Database Design:**
    *   **Primary Key:** A column (or set of columns) that uniquely identifies each row in a table.
    *   **Foreign Key:** A column (or set of columns) in one table that refers to the primary key in another table, establishing a link between them.
    *   **Indexes:** Special lookup tables that the database search engine can use to speed up data retrieval. Automatically created for primary keys. Can be created for other columns.
    *   Normalization (briefly, conceptual): Reducing data redundancy and improving data integrity.
*   **Relationships:**
    *   One-to-Many: e.g., One author can have many books. (Books table has an `author_id` foreign key).
    *   Many-to-Many: e.g., Students can enroll in many courses, and courses can have many students. Requires a **join table** (or associative table) with foreign keys to both tables.
*   **`JOIN` clauses:**
    *   `INNER JOIN` (or just `JOIN`): Returns rows when there is a match in both tables.
    *   `LEFT JOIN`: Returns all rows from the left table, and matched rows from the right table (or NULLs if no match).
    *   `RIGHT JOIN`, `FULL OUTER JOIN` (less commonly focused on in intro).
*   **Race Conditions and Transactions (Conceptual):**
    *   Problems with concurrent access if not handled properly.
    *   Transactions: A sequence of operations performed as a single logical unit of work. All succeed or all fail (atomicity).

## Check-up Questions & Answers

1.  **Q: What is a primary key in a relational database table?**
    *   A: A primary key is a column (or a set of columns) whose values uniquely identify each row in the table. It cannot contain NULL values and must be unique.

2.  **Q: Explain the purpose of a `JOIN` clause in SQL.**
    *   A: A `JOIN` clause is used to combine rows from two or more tables based on a related column between them (typically a foreign key - primary key relationship).

3.  **Q: What SQL command would you use to retrieve all columns for all users whose name is 'David' from a table named `users`?**
    *   A: `SELECT * FROM users WHERE name = 'David';`

4.  **Q: Describe a many-to-many relationship between two entities (e.g., `students` and `courses`) and how it's typically implemented in a relational database.**
    *   A: A many-to-many relationship means one student can enroll in many courses, and one course can have many students. It's implemented using a third "join table" (or associative/junction table), say `enrollments`, which has foreign keys referencing the primary keys of both the `students` table and the `courses` table. Each row in `enrollments` represents a specific student enrolled in a specific course.

5.  **Q: What does the `sqlite3 .schema table_name` command do?**
    *   A: It displays the `CREATE TABLE` statement that was used to define the structure (schema) of the specified `table_name`.

## Surprise or Odd Knowledge Mentioned

*   **SQL is (mostly) declarative:** You describe *what* data you want, not *how* to get it step-by-step (like in C or Python imperative code). The database engine figures out the "how" (query optimization).
*   **`NULL` is tricky:** `NULL` means "unknown" or "missing value," not zero or an empty string. Comparisons with `NULL` (e.g., `column = NULL`) behave unexpectedly; you must use `IS NULL` or `IS NOT NULL`.
*   **The power of Indexes:** David might show a query on a large table running slowly, then add an index and show it running much faster, emphasizing the dramatic performance impact.
*   **Database "Atomicity":** The idea that transactions are "all or nothing." If you're transferring money, you debit one account and credit another. Both must succeed; if one fails, the whole transaction is rolled back.
*   **The ".db" file is the database (for SQLite):** The entire database (schema, data, indexes) is contained in a single file, making SQLite very portable and easy to set up.
*   **Different SQL "dialects":** While SQL is a standard, different database systems (MySQL, PostgreSQL, SQL Server, Oracle, SQLite) have minor variations in syntax or supported features. CS50 usually sticks to features common across most or specific to SQLite.

    *   **Box Model:** Content, padding, border, margin.
    *   Layout techniques:
        *   Floats (older).
        *   Flexbox (for 1D layouts).
        *   CSS Grid (for 2D layouts).
        *   Positioning (`static`, `relative`, `absolute`, `fixed`, `sticky`).
    *   Responsive Design: Using media queries (`@media`) to adapt layouts to different screen sizes.
*   **JavaScript (JS):**
    *   Adding interactivity and dynamic behavior to web pages (client-side).
    *   Syntax similar to C/Python in some ways (variables, operators, control flow, functions).
    *   Including JS: `<script>` tag (in `<head>` or end of `<body>`, external `.js` file).
    *   **Variables:** `var` (older), `let` (block-scoped), `const` (constant).
    *   **Data Types:** Number, String, Boolean, Array, Object, Null, Undefined.
    *   **DOM (Document Object Model):** A tree-like representation of the HTML document that JS can manipulate.
        *   Selecting elements: `document.getElementById()`, `document.querySelector()`, `document.querySelectorAll()`.
        *   Modifying elements: Changing `innerHTML`, `textContent`, style attributes (`element.style.color = 'red'`), adding/removing classes (`element.classList.add()`).
        *   Creating and appending elements.
    *   **Events:** Responding to user actions.
        *   `onclick`, `onmouseover`, `onkeydown`, `onsubmit`.
        *   Event listeners: `element.addEventListener('click', functionName);`

## Check-up Questions & Answers

1.  **Q: What are the primary roles of HTML, CSS, and JavaScript in web development?**
    *   A:
        *   **HTML:** Provides the structure and content of a web page.
        *   **CSS:** Defines the style and presentation (layout, colors, fonts) of the HTML content.
        *   **JavaScript:** Adds interactivity, dynamic updates, and client-side logic to the web page.

2.  **Q: What is the difference between an HTML `id` attribute and a `class` attribute?**
    *   A: An `id` attribute should be unique within an entire HTML document and is used to target a single, specific element. A `class` attribute can be applied to multiple elements, grouping them for styling or JavaScript manipulation. In CSS, IDs are selected with `#idname` and classes with `.classname`. IDs have higher specificity.

3.  **Q: What is the DOM?**
    *   A: The Document Object Model (DOM) is a programming interface for web documents. It represents the page structure (HTML) as a tree of objects, where each object corresponds to a part of the document (e.g., an element, attribute, or text). JavaScript can interact with the DOM to read or modify the content, structure, and style of the document.

4.  **Q: How can you include JavaScript code in an HTML file? Name two ways.**
    *   A:
        *   1. Inline: Using the `<script>` tags directly within the HTML file, either in the `<head>` or, more commonly, at the end of the `<body>`.
        *   2. External file: Placing JavaScript code in a separate `.js` file and linking to it using `<script src="path/to/script.js"></script>`.

5.  **Q: What is the CSS Box Model? List its components from innermost to outermost.**
    *   A: The CSS Box Model describes how HTML elements are rendered as rectangular boxes. Its components are:
        *   1. Content: The actual text, image, or other media.
        *   2. Padding: Transparent space around the content, inside the border.
        *   3. Border: A line around the padding and content.
        *   4. Margin: Transparent space around the border, separating the element from other elements.

## Lectures, Explanations, and Shorts

### Lecture 9:
*   **Client-Side vs. Server-Side:**
    *   Recap: HTML/CSS/JS run in the browser (client-side).
    *   Server-side code (e.g., Python with Flask) runs on the web server, processes requests, interacts with databases, generates HTML to send back to the client.
*   **Web Frameworks:**
    *   What they are: Libraries/tools that simplify web development by providing structure and common functionalities (routing, templating, database integration).
    *   Microframework (like Flask) vs. Full-stack framework (like Django). Flask is more lightweight and flexible.
*   **Flask Basics:**
    *   Installation: `pip install Flask`.
    *   A minimal Flask app:
        ```python
        from flask import Flask
        app = Flask(__name__)

        @app.route("/")
        def index():
            return "Hello, World!"

        if __name__ == "__main__":
            app.run(debug=True)
        ```
    *   **Routes:** Mapping URLs to Python functions using `@app.route('/path')` decorator.
    *   **Request Methods:** `GET` (requesting data), `POST` (submitting data). Specifying methods: `@app.route('/login', methods=["GET", "POST"])`.

    *   Flask uses Jinja2 templating engine.
    *   Separating presentation (HTML) from logic (Python).

        *   `{{ variable }}` for outputting variables.
        *   `{% control_structure %}` for loops, conditionals (e.g., `{% for item in items %}`, `{% if user %}`).
        *   Template inheritance: `{% extends "layout.html" %}`, `{% block body %}`.
*   **Forms:**
    *   HTML forms (`<form method="POST" action="/submit_url">`).
    *   Accessing form data in Flask: `from flask import request`. `name = request.form.get("input_name")`.
    *   Handling `GET` vs. `POST` requests in the same route.
*   **Sessions:**
    *   Maintaining state across multiple HTTP requests (HTTP is stateless).
    *   Using cookies to store a session ID on the client.
    *   Flask's `session` object: `from flask import session`.
        *   `session["user_id"] = user_id`
        *   `user_id = session.get("user_id")`
        *   Requires setting `app.secret_key`.
*   **Layouts and Static Files:**
    *   `layout.html` base template for common structure (header, footer, nav).
    *   Serving static files (CSS, JS, images) from a `static` folder. `url_for('static', filename='style.css')`.
*   **Interacting with Databases (e.g., SQLite via CS50's SQL library or SQLAlchemy):**
    *   Often uses the `cs50` library's SQL module for simplicity:
        ```python
        from cs50 import SQL
        ```

    *   Or a brief intro to SQLAlchemy (an ORM - Object Relational Mapper) for more complex applications.
*   **Redirects and Flashing Messages:**
    *   `from flask import redirect, url_for, flash`.
    *   `return redirect(url_for('index'))` to send user to another page.

*   **Application Structure (Project `finance` as a key example):**
    *   `application.py` (main Flask app).
    *   `templates/` folder (for HTML files).
    *   `static/` folder (for CSS, JS, images).

2.  **Q: How do you define a route in a Flask application that responds to HTTP GET requests at the URL `/dashboard`?**
    *   A:
        ```python
        @app.route("/dashboard")  # Defaults to GET if methods not specified
        def dashboard():
            # ... your Python code ...
            return render_template("dashboard.html")
        ```
        Or explicitly: `@app.route("/dashboard", methods=["GET"])`

    *   A: Flask uses cryptographically signed cookies to store session data on the client-side.         search_query = request.form.get("query")

## Check-up Questions & Answers

1.  **Q: What does it mean for Python to be "dynamically typed"?**
    *   A: It means that variable types are checked at runtime, and you don't need to explicitly declare the type of a variable when you create it. The type is inferred from the value assigned.

2.  **Q: How do you define a block of code in Python (e.g., inside an `if` statement or a `for` loop)?**
    *   A: By indentation. Python uses consistent indentation (typically 4 spaces) to define code blocks, instead of curly braces `{}` like in C.

3.  **Q: Name three built-in mutable data structures in Python and one immutable one (other than basic types like int/str).**
    *   A: Mutable: Lists, Dictionaries, Sets. Immutable: Tuples.

4.  **Q: What is the purpose of the `with open(...) as f:` construct in Python?**
    *   A: It's a context manager for file operations. It ensures that the file is automatically closed when the block is exited, even if errors occur within the block. This helps prevent resource leaks.

5.  **Q: How can you get command-line arguments passed to a Python script?**
    *   A: By importing the `sys` module and accessing `sys.argv`. `sys.argv` is a list where the first element (`sys.argv[0]`) is the script's name, and subsequent elements are the arguments.

## Surprise or Odd Knowledge Mentioned

*   **"Pythonic" way of doing things:** There's often an idiomatic or "Pythonic" way to write code that leverages Python's features for conciseness and readability (e.g., list comprehensions, iterating directly over sequences instead of using index variables).
*   **The Global Interpreter Lock (GIL):** For CPython (the standard implementation), the GIL means that only one thread can hold control of the Python interpreter at any given time, even on multi-core processors. This can limit the performance benefits of threading for CPU-bound tasks (but not I/O-bound tasks). (Often a more advanced aside).
*   **Everything is an object (almost):** In Python, most things, including numbers, strings, functions, and lists, are objects with attributes and methods.
*   **Duck Typing:** "If it walks like a duck and quacks like a duck, then it must be a duck." Python often cares more about whether an object *behaves* as expected (i.e., has the right methods/attributes) rather than its explicit type.
*   **Negative indexing and slicing:** `my_list[-1]` gets the last element. `my_list[::-1]` reverses a list. These convenient features are often highlighted.
*   **The sheer number of available libraries:** David often emphasizes how `pip install some_package` can give you powerful pre-built functionality for almost anything, contrasting with C where you often build more from scratch.
